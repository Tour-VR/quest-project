Execução dos planos com IA

Construindo o TourVR com agentes de IA

Como executar os 21 planos de trabalho com o Claude Code, do zero ao tour no Meta Quest 3
Orientação: Dr. Ciro J. A. Macedo

Para começar

O TourVR é um tour do campus em duas formas. No celular, o visitante lê um QR Code afixado num local (a biblioteca, por exemplo) e vê a história, as fotos e a explicação daquele lugar. No Meta Quest 3, quem ainda não conhece o campus faz uma visita em 360°, passando de um ponto para outro. Tudo é gerenciado por um painel administrativo na web.

Vocês não vão escrever código à mão. O trabalho foi dividido em 21 planos, arquivos de instrução que um agente de IA (o Claude Code) lê e executa. O seu papel é orquestrar: escolher o plano, entregar o prompt ao agente, acompanhar, conferir o resultado com os próprios olhos e avisar o grupo.

Os planos ficam em docs/tasks/, numerados na ordem de execução (001, 002, …). As regras que o agente segue estão em docs/tasks/protocolo-execucao.md. Você não precisa decorar esse arquivo: o agente lê sozinho.

Parte 1 · Preparar o computador (uma vez só)
1

Conta no GitHub e acesso ao projeto

Crie uma conta em github.com, se ainda não tiver. Envie o seu nome de usuário no grupo para ser adicionado à organização Tour-VR. Sem esse acesso o agente não consegue enviar o trabalho.

2

Instalar os programas

Instale pelo site oficial de cada um ou, no Windows, abra o PowerShell e rode os comandos abaixo, um por linha:

winget install Git.Git
winget install Microsoft.VisualStudioCode
winget install GitHub.cli
winget install OpenJS.NodeJS.LTS
winget install Python.Python.3.12
winget install Docker.DockerDesktop

Depois de instalar, reinicie o computador. Abra o Docker Desktop uma vez e aceite os termos. Ele precisa estar aberto sempre que for trabalhar a partir do plano 002.

3

Instalar o Claude Code no VS Code

  1. Abra o VS Code e clique em Extensões (ícone de quadradinhos na barra lateral, ou Ctrl+Shift+X).
  2. Pesquise Claude Code, escolha a extensão publicada pela Anthropic e clique em Install.
  3. Clique no ícone do Claude que aparece no canto superior direito do editor e entre com a sua conta Claude.
4

Ligar o Git à sua conta

No VS Code, abra um terminal (Terminal → New Terminal). Na setinha ao lado do +, escolha Git Bash. Rode:

git config --global user.name "Seu Nome Completo"
git config --global user.email "seu-email@exemplo.com"
gh auth login
gh auth setup-git

No gh auth login, responda: GitHub.com → HTTPS → Yes (autenticar o Git) → Login with a web browser. Copie o código que aparecer, cole na página que abrir no navegador e autorize.

Parte 2 · Baixar o projeto e abrir no VS Code (uma vez só)
5

Clonar o repositório

Escolha uma pasta sem espaços nem acentos no caminho, por exemplo C:\projetos. No terminal Git Bash:

mkdir -p /c/projetos
cd /c/projetos
git clone --recurse-submodules https://github.com/Tour-VR/quest-project.git
cd quest-project
git submodule foreach "git checkout main && git pull"

O projeto tem quatro repositórios: o principal (quest-project) e três submódulos dentro de services/ (backend, frontend e vr-app). A última linha deixa os três na versão mais recente. Depois que o plano 001 estiver concluído, use bash scripts/setup.sh no lugar dela.

6

Abrir o projeto no VS Code

  1. No VS Code: File → Open Folder… e escolha C:\projetos\quest-project (a pasta principal, não uma das de services/).
  2. Se o VS Code perguntar se confia nos autores, responda Yes, I trust the authors.
  3. Abra o terminal e deixe o Git Bash como padrão: Ctrl+Shift+P → Terminal: Select Default Profile → Git Bash.
7

Abrir o Claude Code e testar

Clique no ícone do Claude (canto superior direito) para abrir uma conversa. Confira se ele está trabalhando na pasta quest-project e faça o teste:

Leia docs/tasks/README.md e me diga, em uma frase, qual é o próximo plano disponível para executar, segundo a regra de docs/tasks/protocolo-execucao.md. Não altere nenhum arquivo.

Se ele responder com um número de plano, está tudo pronto.

Pedidos de permissãoO agente pede autorização antes de rodar comandos e editar arquivos. Leia o que ele quer fazer. Pode aceitar comandos dentro do projeto (git, npm, pytest, docker compose). Recuse e avise o grupo se ele pedir para apagar arquivos fora do projeto ou usar push --force.
Parte 3 · O ciclo de um plano

Todo plano passa pelos mesmos estados. O status de cada um aparece no índice docs/tasks/README.md, que você pode ver no GitHub a qualquer momento.

Validado→ Em execução→ Em revisão→ Concluído

Regra de escolha: pegue o menor número com status Validado cujas dependências (coluna Depende de) estejam todas Concluído. Dois alunos podem trabalhar ao mesmo tempo em planos diferentes que já estejam liberados. O agente reserva o plano com o seu nome antes de começar; se outro colega reservou primeiro, ele avisa e sugere outro.

A

Executar — o primeiro prompt

Abra uma conversa nova no Claude Code (uma por plano) e cole o prompt do plano escolhido (Parte 4), trocando <SEU NOME>. O agente vai reservar o plano, ler a documentação, implementar passo a passo, testar e abrir os Pull Requests (PRs) no GitHub. Isso pode levar de 30 minutos a algumas horas: acompanhe e responda aos pedidos de permissão.

No fim, ele entrega um relatório com os links dos PRs, um roteiro de verificação pelo aluno e uma mensagem pronta para o grupo. Faça a verificação e cole a mensagem no grupo.

B

Corrigir — se o orientador pedir ajustes

O orientador revisa os PRs. Se ele comentar pedindo mudanças, abra o Claude Code e cole:

O orientador pediu ajustes nos PRs do plano NNN. Siga o "Prompt 2 — CORRIGIR" de docs/tasks/protocolo-execucao.md para o plano docs/tasks/NNN-slug.md.
C

Fechar — depois que o orientador fizer o merge

Quando o orientador avisar que fez o merge de todos os PRs do plano, cole:

O orientador fez o merge de todos os PRs do plano NNN. Siga o "Prompt 3 — FECHAR" de docs/tasks/protocolo-execucao.md para o plano docs/tasks/NNN-slug.md.

O agente marca o plano como Concluído e diz qual é o próximo disponível. Avise no grupo. Sem o fechamento, o próximo plano não fica liberado.

D

Retomar — se a sessão cair no meio

Fechou o VS Code, caiu a internet ou o computador desligou? Não comece de novo. Cole:

A execução do plano docs/tasks/NNN-slug.md foi interrompida. Siga o "Prompt 4 — RETOMAR" de docs/tasks/protocolo-execucao.md e continue de onde parou. Meu nome: <SEU NOME>

Em todos os prompts, troque NNN-slug pelo nome do arquivo do plano, que aparece na Parte 4 (por exemplo, 001-higiene-orquestrador).

Parte 4 · Os 21 planos e o primeiro prompt de cada um

Cole o prompt do plano numa conversa nova do Claude Code, com o VS Code aberto na pasta quest-project. Troque <SEU NOME> pelo seu nome.

{{PLANOS}}
Parte 5 · Regras de ouro e problemas comuns
!

Regras de ouro

  • Não edite código à mão. Se algo estiver errado, peça ao agente ou avise o grupo.
  • Um plano por conversa. Comece cada plano numa conversa nova do Claude Code.
  • Não faça merge de PR. Quem faz é o orientador.
  • Não pule o fechamento (prompt C). É ele que libera o próximo plano para a turma.
  • Se o agente parar e pedir para avisar o grupo, avise. Ele para quando o plano não bate com o código, e isso precisa de decisão humana.
  • Docker Desktop aberto sempre que for trabalhar, a partir do plano 002.
  • Nunca cole senhas nem chaves no chat do agente, nos commits ou no grupo.
O que aconteceuO que fazer
O agente diz que gh não está autenticadoNo terminal: gh auth login e depois gh auth setup-git (passo 4)
Erro 403 ou permission denied ao enviarSua conta ainda não tem acesso à organização Tour-VR. Avise o orientador
"Plano não disponível"Normal: outro colega reservou, ou falta concluir uma dependência. Use o plano que o agente sugerir
Erro dizendo que o Docker não está rodandoAbra o Docker Desktop, espere aparecer Engine running e peça ao agente para continuar
O agente diz que há arquivos alterados que não são do planoNão deixe descartar sem entender. Pergunte ao agente o que são e, na dúvida, avise o grupo
A sessão terminou por limite de usoEspere o limite renovar e use o prompt D (Retomar)

Como acompanhar o projeto

  1. Índice de planos no GitHub: docs/tasks/README.md no repositório Tour-VR/quest-project. Mostra o status de cada plano e quem está executando.
  2. Grupo do WhatsApp: toda reserva, revisão e conclusão é anunciada com a mensagem que o agente prepara.
  3. O sistema funcionando: a partir do plano 002, o projeto sobe no seu computador com docker compose up. O painel fica em http://localhost:3000 e o app do visitante em http://localhost:3001 (a partir do plano 016).

Dúvida que o agente não resolve vai para o grupo. Ninguém precisa travar sozinho.
